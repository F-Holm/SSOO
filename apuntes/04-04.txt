Multithreading programming

El programa es una entidad pasiva y el proceso activa
Proceso = Tarea (término antiguo)

Concurrencia: Compartir recursos (múltiples colas para un procesador). Simula paralelismo
Paralelismo: Cada cola tiene su procesador

Imagen del proceso = Memoria utilizada por el proceso
Memoria:
- stack
- heap

- código

PCB (Process Control Block):
- ID

Modelo de 5 Estados:

new -> ready <-> running -> terminated
        ^- waiting <|

- new     -> ready:      admitted
- ready   -> running:    scheduler dispatch
- running -> ready:      interrupt
- running -> waiting:    I/O or event wait
- waiting -> ready:      I/O or event completition
- running -> terminated: exit

Modelo de 7 estados:

Suspendido <-> En memoria permanente

- en espera            -> suspendido en espera: lo manda al swap
- suspendido en espera -> en espera             lo manda al swap
- suspendido listo     -> listo:                vuelve a la MP
- listo                -> suspendido listo     proceso admitido pero suspendido por falta de memoria ram

Los SO suelen tener más estados, estos son los mínimos indispensables

Hay ráfagas de cpu e E/S
No se puede saber el largo de una ráfaga pero se puede estimar

Algoritmos:
FIFO: First in First out
  un proceso largo puede llevarse todo el tiempo de procesamiento sin tener en cuenta duracion ni prioridad, solo orden de llegada
  Es sin desalojo
SJF: Shortest Job First
  sin desalogo: se elige el proceso con menor tienpo restante
  con desalojo: si llega un procceso más corto que el restante de ráfaga actual, se detiene y se inicia la nueva ráfaga
  Puede producir Starvation cuando no paran de llegar proecsos con ráfagas más cortas
SJF con estimación:
  Est(n+1) = k*R(n) + (1-k)*Est(n) ; 0 <= k <= 1
  Est(x) = duracion de ráfaga estimado de x
  R(x) = duracion de la ráfaga de x
  Restar 1 a la Estimación después de cada ejecución hasta terminar la ráfaga o llegar a 0 (máxima)
  Siempre dan como dato la estimación inicial o los datos para calcularla (ráfaga anterior y estimacion anterior)
Prioridades: puede ser con o sin desalojo
  Usa el envegecimiento (aging) para evitar starvation
HRRN: Highest Response Ratio Next
  con o sin desalojo (suele ser sin desalojo)
  mucho overhead
  es una adaptación de un SJF sin inanición
  RR = (S + W) / S = 1 + W/S
    S = Duración de la prócima ráfaga
    W = Tiempo de espera en READY
RR: Round Robin
  Quantum = cantidad máxima de tiempo
  Siempre con desalojo
  si hay n procesos en la cola de listos y el cuantum es q, ningun proceso espera más de q*(n-1) unidades de tiempo
  No minimiza el tiempo de espera, lo hace previsible
  Un quantum demasiado grande se comporta como FIFO
  Si el quantum es demasiado chico hay overhead

Cuando hay empate por FIFO, el que estaba en cpu siempre tiene prioridad
